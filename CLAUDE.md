---

## Animation Language

- Clip-path typography reveals
- Short mechanical text scrambling for technical metadata
- Subtle border-state hover
- Corner indicators
- Slide-in button inversion
- Interaction-triggered SVG signals
- Restrained cursor interaction
- No unnecessary perpetual animation

### Motion Timing

| Token | Duration |
| ----- | -------- |
| fast | ~150 ms |
| standard | ~300 ms |
| emphasis | ~450 ms |
| reveal | ~650 ms |

---

## Accessibility

- Respect `prefers-reduced-motion`.
- All interactive elements must be keyboard accessible.
- Do not communicate important information through animation alone.
- Maintain clear focus states.
- Maintain adequate contrast.

---

## Performance

- Prefer CSS / SVG / Motion over canvas / WebGL.
- Avoid unnecessary computation.
- Optimize images.
- Lazy-load non-critical assets.
- Keep animation GPU-friendly.
- Avoid unnecessary client-side JavaScript.

---

## Architecture

- Use reusable components.
- Keep page content separate from presentation.
- Keep project data in typed data files.
- Avoid giant monolithic components.
- Avoid duplicated markup.
- Prefer clear component boundaries.
- Keep content easy to update without changing presentation logic.

---

## Agent Behaviour

- Do not invent project facts, achievements, statistics, clients, technologies or results.
- Do not silently change approved content or positioning.
- Do not redesign the visual identity without explicit approval.
- Do not install additional dependencies without explaining why first.
- Before major architectural changes, explain the proposed approach.
- Prefer the simplest technically sound solution.
- Do not build unnecessary features merely because they are technically possible.
- When uncertain about an important design or architectural decision, stop and ask rather than guessing.
